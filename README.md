# Swimming Management System

A REST API for managing a swimming club's swimmers, coaches, and managers, built with Spring Boot and Spring Data JPA.

This is a learning project focused on clean layered architecture: controllers handle HTTP, services hold business logic behind interfaces, and repositories handle persistence via Spring Data JPA.

## Architecture

The application follows a standard three-layer Spring Boot structure:

```
HTTP Request
     │
     ▼
┌─────────────┐
│ Controller  │  Request mapping, JSON serialization
└─────────────┘
     │
     ▼
┌─────────────┐
│  Service    │  Business logic, coded against interfaces
└─────────────┘
     │
     ▼
┌─────────────┐
│ Repository  │  Spring Data JPA, extends JpaRepository
└─────────────┘
     │
     ▼
   MySQL
```

Each domain (Swimmer, Coach, Manager) has its own controller, service interface, service implementation, repository, and entity. Services are injected via constructor injection rather than field injection.

## API Reference

All endpoints return JSON. Base URL: `http://localhost:8080`

### Example

Create a swimmer:

```bash
curl -X POST http://localhost:8080/api/swimmer \
  -H "Content-Type: application/json" \
  -d '{
        "firstname": "Youssef",
        "lastname": "Wael",
        "age": 21,
        "team": "Senior"
      }'
```

Response:

```json
{
  "id": 1,
  "firstname": "Youssef",
  "lastname": "Wael",
  "team": "Senior",
  "age": 21
}
```

## Getting Started

### Prerequisites

- JDK 25 or later
- MySQL 8 running locally (or use the H2 option below)
- No Maven install needed — the wrapper is included

### 1. Clone

```bash
git clone https://github.com/Jounova1/SwimmingManagementsystem.git
cd SwimmingManagementsystem/demo
```

### 2. Create the database

```sql
CREATE DATABASE swimmers_db;
CREATE USER 'springstudent'@'localhost' IDENTIFIED BY 'your_password';
GRANT ALL PRIVILEGES ON swimmers_db.* TO 'springstudent'@'localhost';
FLUSH PRIVILEGES;
```

### 3. Configure credentials

`src/main/resources/application.properties` reads the database password from an environment variable:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/swimmers_db
spring.datasource.username=${DB_USERNAME:springstudent}
spring.datasource.password=${DB_PASSWORD}
```

Set it before running:

```bash
export DB_PASSWORD=your_password     # Windows: set DB_PASSWORD=your_password
```

### 4. Run

```bash
./mvnw spring-boot:run     # Windows: mvnw.cmd spring-boot:run
```

The API starts on `http://localhost:8080`. Hibernate creates the tables on first run.

### Running without MySQL

To try the project with no database setup, add H2 to `pom.xml`:

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

and swap the datasource properties:

```properties
spring.datasource.url=jdbc:h2:mem:swimmers_db
spring.datasource.username=sa
spring.datasource.password=
spring.datasource.driver-class-name=org.h2.Driver
spring.h2.console.enabled=true
```

The H2 console is then available at `http://localhost:8080/h2-console`.

## Roadmap

Ordered roughly by priority:

1. **Entity relationships** — add `@ManyToOne` from `Swimmer` to `Coach`, extract `Team` into its own entity.
2. **Validation** — bean validation (`@NotBlank`, `@Min`) on entity fields, `@Valid` on request bodies.
3. **Error handling** — a `@RestControllerAdvice` returning structured error responses instead of raw 500s.
4. **DTOs** — separate request/response models so JPA entities aren't exposed directly over HTTP.
5. **Spring Security** — JWT or session-based auth with `MANAGER` / `COACH` / `SWIMMER` roles and BCrypt-hashed passwords.
6. **Tests** — unit tests for the service layer, `@DataJpaTest` for repositories, `@WebMvcTest` for controllers.
7. **API documentation** — OpenAPI/Swagger UI.
8. **Thymeleaf front end** — server-rendered dashboards per role.

Longer term: training session scheduling, race results, attendance tracking, and performance analytics.
